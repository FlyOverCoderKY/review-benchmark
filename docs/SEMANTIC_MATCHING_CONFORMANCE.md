# Semantic matching conformance

Status: public-safe, unlabeled calibration corpus. It is not an answer key or an
official benchmark release.

The corpus at `fixtures/semantic-conformance-v0.1/corpus.json` contains 60
reference/candidate finding pairs in 54 assignment groups. It is synthetic under
the repository's MIT license and contains no private task material. Six pairs
exercise each of these construction strata:

- equivalent paraphrases;
- related but distinct defects;
- unrelated findings;
- duplicate restatements;
- one comment bundling multiple defects;
- the right defect attributed to the wrong location;
- partial trigger or impact descriptions;
- severity disagreement;
- valid out-of-diff findings; and
- adversarial keyword overlap.

The stratum is an author-declared coverage category, not a human match decision.
Blinded reviewers do not receive it. In particular, categories such as partial
descriptions and wrong locations deliberately contain boundary cases whose final
disposition must come from the review process rather than the generator.

## Human labeling protocol

Use at least two independent reviewers followed by a separate adjudication pass.
Give reviewers only queues generated by `semantic-blind`, not the source corpus.
Use opaque reviewer IDs rather than names or email addresses in committed data.

For every presented pair, a reviewer selects:

- `match` when the candidate identifies the same underlying defect with enough
  specificity to distinguish it from nearby defects;
- `no-match` when it identifies a different defect, an unrelated concern, or a
  keyword-only resemblance; or
- `insufficient-evidence` when the supplied finding text cannot support either
  conclusion.

Severity disagreement alone does not change defect identity. A path discrepancy
does matter when it falsely attributes the cause or would materially misdirect a
fix; an adjacent manifestation location may still be usable when the explanation
unambiguously identifies the cause. An out-of-diff location is not automatically
invalid when the finding explains a cross-file regression introduced by the
change. For bundled candidates, label each presented edge independently; the
evaluator later enforces one-to-one assignment so one unsplit comment cannot
receive recall credit for two reference findings.

Each completed verdict requires a written rationale. Setting `status` to
`complete` activates the schema rule that rejects null verdicts and rationales.
No completed human label file ships with v0.1.

Create two independently shuffled, stratum-blinded queues:

```bash
python -m review_benchmark semantic-blind \
  fixtures/semantic-conformance-v0.1/corpus.json \
  --label-set-id reviewer-a-v1 --reviewer-id reviewer-a \
  --out labels/reviewer-a.json
python -m review_benchmark semantic-blind \
  fixtures/semantic-conformance-v0.1/corpus.json \
  --label-set-id reviewer-b-v1 --reviewer-id reviewer-b \
  --out labels/reviewer-b.json
```

After both reviewers finish, generate only the disputed pairs:

```bash
python -m review_benchmark semantic-disagreements \
  fixtures/semantic-conformance-v0.1/corpus.json \
  labels/reviewer-a.json labels/reviewer-b.json \
  --disagreement-set-id adjudication-v1 \
  --out labels/disagreements.json
```

The adjudicator fills `adjudicated_verdict` and `adjudicator_rationale` for every
entry and changes the disagreement file's status to `resolved`. Then combine the
unanimous human decisions with those resolutions:

```bash
python -m review_benchmark semantic-adjudicate \
  fixtures/semantic-conformance-v0.1/corpus.json \
  labels/disagreements.json \
  labels/reviewer-a.json labels/reviewer-b.json \
  --label-set-id adjudicated-v1 --adjudicator-id adjudicator-a \
  --out labels/adjudicated.json
```

The combiner verifies the corpus digest, source label-set identities, exact
disagreement set, completed rationales, and unchanged blinded finding text. It
cannot invent a disposition: unresolved or omitted disagreements fail closed.

## Matcher evaluation

A matcher emits one `match` or `no-match` decision for every pair using
`schemas/semantic-matcher-decisions.schema.json`. Pin its name and version. Then
compare it with the completed adjudicated labels:

```bash
python -m review_benchmark semantic-evaluate \
  fixtures/semantic-conformance-v0.1/corpus.json \
  matcher-decisions.json labels/adjudicated.json \
  --out evaluation.json
```

The report contains ordinary pair-classification counts and assignment-aware
precision and recall. For every group, the evaluator independently computes the
maximum cardinality of the human-approved, matcher-approved, and common edge
sets. A duplicate pair or bundled comment therefore cannot multiply credit. An
`insufficient-evidence` human label is excluded from pair accuracy and from both
assignment graphs.

The conformance score calibrates matcher behavior; it does not replace per-task
adjudication or prove that a semantic model generalizes to private findings.

## Contracts and reproducibility

The versioned contracts are:

- `schemas/semantic-conformance-corpus.schema.json`;
- `schemas/semantic-conformance-labels.schema.json`;
- `schemas/semantic-conformance-disagreements.schema.json`;
- `schemas/semantic-matcher-decisions.schema.json`; and
- `schemas/semantic-conformance-evaluation.schema.json`.

Regenerate or verify the corpus with:

```bash
python scripts/generate_semantic_conformance.py
python scripts/generate_semantic_conformance.py --check
```

Once humans complete v0.1, preserve the corpus and labels immutably. Corrections
or rubric changes require a new corpus/label identity and a documented
disposition rather than rewriting the historical decisions.
